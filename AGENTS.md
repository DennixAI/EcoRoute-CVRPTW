## 3. Mathematical contract and final modeling review

Let C={1,…,n}, V={0}∪C, F={1,…,K}, and A={(i,j): i≠j}. Depot is 0. Inputs: finite nonnegative distances d_ij and static travel durations t_ij; customer demand q_i≥0, service s_i≥0, service-start window [a_i,b_i] with 0≤a_i≤b_i; common capacity Q>0 and integer K>0; depot [a_0,H] with finite H≥a_0≥0, zero depot demand/service. Matrices need not satisfy symmetry or triangle inequality. Coordinates are optional when matrices are supplied. Distances and durations are separate parameters, equal for native benchmark cases.

Every customer appears exactly once on one nonempty customer sequence; no split demand. Each sequence represents 0→customers→0, one trip per active truck, with no internal depot IDs. At most K sequences; unused trucks have no customers/arcs/cost/schedule. Sum of demands per sequence ≤Q. Zero-demand customers still require service. Aggregate demand ≤KQ and max demand ≤Q are necessary, not sufficient (three demands of 6 cannot fit two trucks of capacity 10).

For a route, choose departure T∈[a_0,H]. Propagate arrival A_j=D_i+t_ij (first arrival T+t_0j), service start S_j≥max(A_j,a_j), departure D_j=S_j+s_j, and waiting W_j=S_j−A_j≥0. Require S_j≤b_j and depot return R=D_last+t_last,0≤H. Service may **finish after b_j**, provided depot return is feasible. Default earliest propagation chooses T=a_0 and S=max(A,a). Under static travel and no extra constraints, it suffices to establish temporal feasibility of a fixed order; it does not optimize routes or departure times. Explicit later feasible departures are allowed. Units are native elapsed-time units, not assumed minutes, GPS coordinates or time zones.

Notebook MILP, retained for final validation:

- Binary x_ijk for arc use, y_ik for assignment, z_k for activation; continuous order u_ik. No x_iik.
- Minimize Σ_k Σ_(i,j) d_ij x_ijk. Every customer: Σ_k y_ik=1. For each i,k, both incoming and outgoing arc sums equal y_ik. Depot outgoing and incoming sums each equal z_k. Require y_ik≤z_k and Σ_i q_i y_ik≤Qz_k.
- Order bounds y_ik≤u_ik≤n y_ik. For distinct customers, u_jk≥u_ik+1−(n+1)(1−x_ijk). The coefficient **n+1**, not n, handles inactive assignments. Retain order-based subtour elimination even for zero demand, zero travel/service or coincident coordinates.
- Continuous customer A_ik,S_ik,D_ik∈[0,H y_ik]; a_i y_ik≤S_ik≤b_i y_ik; S_ik≥A_ik; D_ik=S_ik+s_i y_ik. Derived W=S−A. Depot variables are separate T_k,R_k with a_0 z_k≤T_k≤R_k≤H z_k.
- Two-sided activation: |A_jk−D_ik−t_ij|≤M_ij(1−x_ijk) for customer arcs; |A_jk−T_k−t_0j|≤M_0j(1−x_0jk) for outbound depot legs; |R_k−D_ik−t_i0|≤M_i0(1−x_i0k) for returns. These are pairs of linear inequalities, not nonlinear absolute-value solver constraints. Valid M_ij=H+t_ij follows from [0,H] time bounds. Do not use arbitrary huge constants, infinity, a single cyclic depot time variable, or clip windows. Optional z_k≥z_(k+1) only removes interchangeable vehicle labels.

Complexity: polynomial reduction **from TSP to CVRPTW**, using one truck, unit demands, Q=n, zero service, t=d and all windows [0,(n+1)max d]. For finite nonnegative rational inputs the distance-budget decision problem has polynomial route verification and is NP-complete; optimization is NP-hard. Avoid reversing the reduction. Full formulation has O(Kn²) size, which is not a measured runtime claim or a scalable solution algorithm.

The chart explicitly counts arc variables. No core formulation or existing visualization was replaced. Notebook checklist ticks and saved outputs are not tutor approval or a MILP solver/proof certificate.

## 9. Executable infrastructure and verification commands

After environment setup in §5, run these commands from the repository root. Use a new campaign/report directory on every invocation; existing artifacts are preserved:

```bash
python -m unittest discover -v
python scripts/verify_dataset.py --output reports/verification/<unique-run-id>
python scripts/run_modeling.py --strict
python scripts/run_benchmarks.py --reference-fixture --output results/<unique-reference-fixture-id>
python scripts/run_benchmarks.py --manifest /path/to/campaign.json --output results/<unique-external-id>
```

Angle-bracket names are placeholders to replace, not literal shell input. `verify_dataset.py` records all 356 checks/failures, per-file and collection SHA256, source manifest, Python/dependency versions, evaluator source hashes, Git state, hardware and elapsed audit time in CSV/JSON plus a report. It exits nonzero after recording failures. `verify_collection(strict=True)` raises CollectionVerificationError carrying the entire report after checking available pairs. Normal missing-data runs are NOT RUN; any malformed available pair is FAIL even in an incomplete collection. No silent successful partial audit.

`run_benchmarks.py --reference-fixture` replays 20 distinct test fixtures spanning the six sizes and C/R/RC distributions, plus one disjoint development fixture, twice (seeds 0 and 1). These labels exercise the split mechanism; they do not freeze the future held-out set or tune anything. Costs/gaps must reproduce the published routes, generally zero gap. Search/execution time is null because no search ran; parsing/reference/evaluation timings are measured. A fixture can PASS infrastructure validation while its algorithm-quality assessment remains NEEDS IMPROVEMENT / no executed solver evidence.

`CVRPTWInstance` is the authoritative shared solver input. `Solver(instance, config, seed, time_limit) -> SolverResult(routes, departure_times=None, status='completed', claimed_cost=None, trace=[], metadata={})`. Use a top-level pickleable adapter; no adapter is implemented here. `run_campaign(plan, data_root, output, solvers={variant_id: adapter})` accepts a plan with mode=solver; spawn imports must be inside the normal `if __name__ == '__main__':` entry-point guard. The adapter gets the static instance/config/seed/limit, never paired reference routes/costs. Spawn reconstructs the read-only instance; parent validation uses its independent original. Initialization and child-process startup count toward the enforced wall-clock budget. Record child callable time separately. manifest.json explicitly defines every timing boundary. End-to-end attempt time measures adapter/evaluation and preliminary artifact writes; shared per-instance parsing/reference checks and final result/summary writes are excluded and separately disclosed. No cached parsing time is added to fabricate measured attempt duration. Hard deadlines kill the child and record timeout/no incumbent; adapters may return a feasible timeout incumbent before the deadline. Streaming incumbent recovery and memory/thread/CPU-affinity enforcement are not implemented. Record and externally control resources before fair solver runs. A timeout overrun or unknown imported timing cannot earn PASS.

`evaluate_solution(instance, SolverResult, read_reference(instance, paired_sol))` is the reusable offline scoring boundary. It recomputes customer coverage, duplicates, load, fleet, waiting/service-start/depot schedules and distance; routes are customer-only internal IDs. Optional departures correspond to nonempty routes. No eligible cost/gap for invalid routes; missing or invalid reference keeps gap null with a reason. Solver claimed-cost mismatches and negative gaps are visible and block automatic quality PASS pending review. Reference status is missing_reference/invalid_reference/verified, with supplied/recomputed positive cost and SHA256. Raw capacity/time violation magnitudes and tolerance remain in schedules/totals. `check_routing_equations` additionally tests full routing arrays x(K,N,N), y/u(K,n), z(K), including MTZ rejection of disconnected zero-time/zero-demand cycles. `check_temporal_equations` retains explicit checks under Python -O.

Offline manifest format (`path` values are relative to the manifest, `.sol` or JSON accepted):

```json
{
  "plan": {
    "mode": "external",
    "splits": {"development": ["Solomon/C102.vrp"], "test": ["Solomon/C101.vrp"]},
    "seeds": [0, 1],
    "variants": [{"id": "external-v1", "version": "commit-or-version", "config": {}}],
    "time_limits": {"default": 30.0},
    "thresholds": {"average_gap": 3.0, "investigate_gap": 7.0, "min_test_instances": 20, "min_seeds": 2}
  },
  "solutions": [{"variant": "external-v1", "instance_id": "Solomon/C101.vrp", "seed": 0, "path": "saved.sol"}]
}
```

This small format example intentionally cannot PASS: one test instance, no second seed file, no development output and imported timing. Every Cartesian variant × instance in BOTH declared splits × seed is persisted; missing supplied solutions become no_solution attempts. Add ≥20 genuinely untouched test instances and all files for real external comparisons. JSON solution files use SolverResult keys; unknown recorded metadata may go in metadata. No solver feasibility or distance flag is trusted. Set per-instance time_limits using relative .vrp IDs, with optional default. Thresholds are configurable; minimum test count cannot drop below 20 nor minimum repeated seeds below 2. investigations[variant_id][instance_id] holds a nonempty documented cause/remediation for >7% outliers. A lower threshold is permitted, never hide changed targets.

Every campaign contains manifest.json, split.json, runs.jsonl/CSV, summary.csv, family_summary.csv, comparison.csv/JSON/Markdown/PNG, paired_comparisons.json and per-attempt config/result/routes/schedule/trace/log JSON with checksums. Instance/reference hashes are frozen before runs and rechecked afterwards. Exact evaluator sources are archived in evaluator_sources/ alongside hashes and dirty Git state; commit infrastructure and algorithm adapters before final experiments. The input/reference hashes plus archived raw files make campaigns comparable across algorithms. Results are outside ignored outputs/; never overwrite previous campaigns. If interrupted, per-attempt result.json and flushed runs.jsonl survive; no resume/recovery CLI exists yet. Campaign completion requires all planned attempts, not just available records.

Statistics: per-instance mean/median/best/worst/sample SD gaps, timing mean/median/min/max/sample SD, vehicles and failures; equal-weight mean of instance means; family tables and feasibility denominators. Paired exploratory bootstrap uses instance mean differences, 2,000 resamples, fixed seed 2026 and unadjusted 95% percentile intervals. It records excluded pairs; it makes no significance claim and does not replace a predeclared final statistical plan or multiple-comparison policy. comparison.png shows instance gaps and actual measured runtime/scaling where available; reference imports display “No solver runtime measured”.
